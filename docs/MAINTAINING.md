# 游戏优化助手 —— 开发与维护说明

这份说明是给你（维护者）看的，不会发给使用工具的人。给对方的说明书是
`游戏优化助手\使用说明.txt`。

## 1. 交付物

```
outputs\
  游戏优化助手.zip          <- 直接发给朋友的压缩包（内含一个同名文件夹）
  游戏优化助手\
    GameOptimize.ps1        <- 主程序：只读采集 + 问诊 + 诊断 + 边玩边记录 + 生成报告和优化脚本
    1-开始体检.bat           <- 双击入口：静态体检（纯 ASCII 内容，无需管理员）
    2-边玩边记录.bat         <- 双击入口：边玩边记录（纯 ASCII 内容，无需管理员）
    3-一键回滚.bat           <- 一键回滚上一次应用过的改动（会请求管理员）
    4-开游戏前整备.bat       <- 双击入口：进游戏前整备（纯 ASCII 内容，无需管理员）
    PreGame.ps1             <- 开游戏前整备脚本：停/恢复后台程序 + 内存体检 + 守护
    使用说明.txt
```

对方首次运行时，会在同一目录下自动生成两个文件夹：

- 体检走 `优化与方案\`：报告（Markdown）、采集数据（JSON）、个性化优化脚本，
  以及 `3-预演不改动.bat` / `4-真正应用优化.bat` / `5-一键回滚.bat`。
- 边玩边记录走 `性能记录\`：实测报告（Markdown）、逐秒原始采样（JSONL）、
  汇总数据（JSON）、补充优化脚本 `Optimize-<游戏>-监控补丁-<时间>.ps1`，
  同一组 3/4/5 号 bat 也会跟着生成。
- 开游戏前整备走 `开游戏前整备\`：`config.json`（停哪些、恢复哪些，可以直接改）、
  `state.json`（这次停了哪些进程、程序路径和内存）、`整备日志-<时间>.txt`。

## 2. 源码在哪、怎么改完重新打包

源码在 `work\src\`，按顺序拼成一个文件：

| 文件 | 内容 |
|---|---|
| `GameOptimize.ps1` | param 块、终端输出工具、问答引擎、只读采集、诊断规则、报告生成 |
| `GameOptimize.extra.ps1` | 优化脚本生成器（内含生成脚本的模板）+ 改动项清单 `$script:TweakCatalog` |
| `GameOptimize.monitor.ps1` | 边玩边记录：只读采样、卡顿判定、实测报告、补充优化脚本（-Monitor 模式） |
| `GameOptimize.extra2.ps1` | 游戏安装位置定位、启动器 bat 生成、主流程 |

另外 `work\assets\PreGame.ps1` 是「开游戏前整备」的独立脚本，不参与引擎拼接，
由 `build.ps1` 原样复制到成品目录（同样写 BOM）；配套入口 `work\src\4-开游戏前整备.bat`
和其他 bat 一样保持纯 ASCII。它要停哪些进程由 `开游戏前整备\config.json` 决定，
默认值写在脚本的 `Get-DefaultConfig` 里，改默认值记得同时改那里的注释。

改完源码后运行打包脚本（会顺便做语法自检，语法不过不会出包）：

```
powershell -NoProfile -ExecutionPolicy Bypass -File work\build.ps1
```

### ⚠️ 三个必须知道的编码坑

1. **补丁/编辑器写出来的 `.ps1` 默认没有 BOM。** Windows PowerShell 5.1 会把没有 BOM 的
   非 ASCII 脚本按本地代码页（中文系统是 GBK）读取，中文不仅会变乱码，还可能吞掉后面
   一个字符（比如引号或换行），变成莫名其妙的语法错误。所以源码本身保持无 BOM 没关系，
   但**凡是会被 powershell.exe 直接执行的脚本，必须先加 BOM**：

   ```
   powershell -NoProfile -ExecutionPolicy Bypass -File work\addbom.ps1 work\build.ps1
   ```

   `build.ps1` 会自动给成品（`GameOptimize.ps1`、`使用说明.txt`）写 BOM；`build.ps1`
   自己改过之后要重新跑一次 `addbom.ps1`。

2. **`.bat` 一律保持纯 ASCII 内容。** cmd 按本地代码页读 bat，中文容易乱；所以
   `1-开始体检.bat`、`2-边玩边记录.bat`、`3-一键回滚.bat` 以及程序生成的 3/4/5 号 bat 都不含中文——
   需要引用中文文件名时用通配符（`for %%f in ("Optimize-*.ps1")`）绕开。

3. **打补丁时，新增行里的 ASCII 双引号会被静默吞掉。** 所以新写的代码一律用单引号包字符串，
   确实需要双引号时用 `[string][char]34` 拼出来；`.bat` 里同理，尽量改成不加引号的写法
   （例如 `cd /d %~dp0`），或改用 PowerShell 直接改文件。另外，补丁里的多个 hunk 要按
   在文件中出现的先后顺序排列，否则会报找不到上下文；上下文行本身也不能含 ASCII 双引号。

## 3. 边玩边记录模块（monitor）怎么工作

入口：`GameOptimize.ps1 -Monitor`（`2-边玩边记录.bat` 就是调它）。全程只读、不需要管理员，
只在最后生成一份补充优化脚本（同样先预演、可回滚）。

流程：

1. `Get-MonitorContext` 读轻量机器信息（CPU、独显与显存、内存、系统版本、电源计划、
   处理器最大状态、游戏模式、DVR、HAGS、VBS），并带出游戏盘符的介质类型（SSD/HDD）。
2. `Test-MonitorAbility` 探测这台机器上哪些计数器真的能读（GPU、内存、磁盘、网络），
   读不到的项写进报告说明与限制，不会让流程失败。
3. `Invoke-MonitorRun` 等游戏进程出现（最多 4 分钟）→ 每秒一个采样点 → 键盘监听：
   回车 = 标记卡顿点，Ctrl+C = 提前结束；时间到、或游戏退出（连续 15 秒没再看到进程）
   也会自动收尾。每 15 秒在控制台刷一行状态；单次采样超时则自动放慢节奏。
4. `Get-MonitorAnalysis` 出统计：跳过进游戏后的前 60 秒（加载期噪声），再算
   avg/p95/max/min、30 秒一段的时间线、显卡与 CPU 占用分档、后台进程排行、
   磁盘 IO 排行，以及可疑卡顿时刻（磁盘不低于 90%、提交比例不低于 90%、
   可用内存低于 0.8GB、硬页错误偏高、游戏核吃满、网络不低于 8MB/s、用户标记）。
5. `Get-MonitorVerdict` 把数据翻译成结论：显卡满载/接近/有余力、CPU 瓶颈、内存不足、
   显存吃紧、磁盘忙、后台抢资源、后台下载、电池供电、电源计划不是高性能、CPU 最大频率被限，
   分别落到 `Add-Finding`（问题项）、`Add-Manual`（手动步骤）、`Add-Tweak`（脚本代劳项）。
6. `New-MonitorReport` 生成 Markdown 报告；`New-OptimizeScript` 用同一套模板生成补充脚本，
   并配上 3/4/5 号 bat。

采样节奏（`Get-MonitorTick`，全部只读）：

| 频率 | 内容 |
|---|---|
| 每个 tick | 进程快照：整机 CPU、游戏进程 CPU、游戏进程内存、后台进程排行 |
| 每 3 个 tick | 内存（可用/提交/硬页错误）、磁盘繁忙、每个进程的显存与 GPU 引擎占用 |
| 每 3 个 tick（与上一项错开） | 显卡 3D 引擎利用率、整机与游戏进程显存 |
| 每 5 个 tick | 网络吞吐、每个进程的磁盘 IO 累计量 |

慢变量不是每轮都采，采到一次后向前补齐（`$state.lastMetrics`），所以报告里每一行都是
完整画面，不会整片 `--`；代价是平均值按 tick 时间加权，而不是按采样次数加权。

判定阈值都在 `Get-MonitorVerdict` 里，改之前先想清楚会不会和体检模式的结论打架。

去重：`Get-MonitorScriptPlan` + `Read-ExistingTweakIds` 会读同目录与上级目录里最近的
`Optimize-*.ps1`，已经包含的改动项不再重复写进新脚本，报告里用一句话说明跳过了哪些。

## 4. 程序的设计约束（改代码时请保持）

- **默认只预演**：优化脚本不加 `-Apply` 时只打印计划，一个字都不改。
- **每项改动都可回滚**：应用前把原值（含注册表值类型）写进
  `optimize-logs\journal.json`，`-Revert` 按相反顺序还原，并把日志归档。
- **改动项只从 `$script:TweakCatalog` 里选**，一次交付不超过 8 项。
- **有安全代价的项**（关闭 VBS / 内存完整性）放在 `Risky` 后面，必须显式加
  `-AllowRisky` 才会执行，且在报告里单独写明代价。
- **不做**：不关 Defender 实时保护、不关 Windows 更新、不批量禁用系统服务、
  不碰游戏文件和反作弊进程、不做超频改电压、不装第三方"优化/清理"工具。
- 需要管理员权限的项在预演阶段也会显示"将要改成什么"，只是不会真的写。

## 5. 诊断规则大致覆盖哪些情况

（记录模式的判定规则见第 3 节；下面是体检模式。）

显卡档次与画质档/分辨率是否匹配、是否只有核显、驱动是否太旧、双显卡是否把游戏
交给核显、内存是否吃紧、后台程序与第三方安全软件占用、游戏是否装在机械硬盘、
磁盘剩余空间、硬盘健康、电源计划是否压 CPU 频率（厂商自定义计划按名字判断，
同时读注册表里的"处理器最大状态"作为客观依据）、笔记本是否在用电池、
显示器刷新率是否开满、垂直同步/窗口化带来的输入延迟、散热与温度、
有线还是无线、游戏模式/后台录制/HAGS/VBS 的开关状态、待重启、启动项数量。

覆盖不到、只能在报告里写"未能确认"的：温度（多数主板不开放接口）、显卡控制面板
设置、游戏内画质档、部分显示器的刷新率列表。

## 6. 已经做过的验证

- **端到端**：`work\test-answers.json` + `-NonInteractive` 跑完整流程，
  生成报告、采集数据、优化脚本和 3 个 bat，并逐条核对报告关键内容。
- **真实双击路径**：把成品复制到带空格的中文路径（`work\e2e\游戏 优化助手 测试`），
  实际双击 `1-开始体检.bat` 走完 13 道题、生成产物；再双击
  `3-预演不改动.bat` 验证预演链路。
- **应用/回滚夹具**：`work\test-apply-revert.ps1` 把生成脚本里的注册表路径改到
  临时键 `HKCU\Software\_GameOptScratch`，依次跑预演 → 应用 → 回滚，
  断言"预演不产生任何改动""应用写入新值并记录原值和类型""回滚还原原值并归档日志"，
  跑完删除临时键。全部 PASS。
- **PowerShell 5.1 陷阱**：`work\microtest.ps1` / `microtest2.ps1` 记录了实测结论——
  `@($someListOfObject)` 在 5.1 上会抛 "Argument types do not match"，
  必须用 `[object[]]$list`；`List[string]` 和普通数组不受影响。
- **记录模式非交互跑通**：`-Monitor -GameProcess notepad -MonitorSeconds 45 -NonInteractive`，
  四种收尾都验过：时间到、Ctrl+C、游戏退出（连续 15 秒没再看到进程）、没有游戏进程时按整机记录；
  并逐项核对报告里的显卡/显存/内存/磁盘/网络/后台排行与自动建议。
- **记录模式的真实双击路径**：成品复制到 `work\test-bat\`，用 `2-边玩边记录.bat` 走完
  整个交互流程（选游戏 → 填 exe → 选时长 → 帮启动 → 回车标记卡顿 → Ctrl+C 结束 →
  答手感 → 打开报告），确认 `性能记录\` 里的 4 类产物和 3/4/5 号 bat 都正确。
- **记录模式预演链路**：确认生成的补充脚本不带 `-Apply` 时只打印计划、不改任何设置。
- **开游戏前整备**：拿记事本和画图当替身（临时配置 `apps = notepad`、`gameProcess = notepad`），
  逐条验过四件事——预演模式不改动（记事本还在、不生成 state.json）、应用时会关掉并记下
  名字/PID/路径/内存、`-Revert` 能把它们重新启动起来、`-Apply -Watch` 在游戏退出后
  自动收尾并恢复（实测：关掉替身游戏后 21 秒收工，画图已自动恢复）。
  中途踩到的坑：`$doWatch = $true` 必须写在提示块外面，否则 `-Watch` 会走成「不守护」。

## 7. 已知限制

- 必须**先解压再运行**；在压缩包里直接双击不行。
- 游戏安装位置靠 Steam 库文件、卸载信息表和常见目录推断，找不到时报告里会写
  "未能确认"，可以让对方在最后一题手填路径。
- 厂商电源计划只能按名字猜性能档（联想"野兽模式"、华硕性能模式之类），
  猜不准时会退化成"让你自己去控制面板看一眼"。
- 显示器刷新率列表来自 WMI，个别面板读出来的最高值可能偏低；只有"支持值高于当前值"
  时才会提示，避免给出错误建议。
- 目前只针对 Windows，且假定系统是 PowerShell 5.1（Win10/11 自带）。
- 记录模式读不到 GPU 计数器时（老显卡、精简系统），显卡相关结论会降级成未能读取，
  报告里会写明；帧数（FPS）只能靠用户自己填。
- 采样 1~2 秒一次，比这个周期更短的瞬时抖动抓不到；用户按回车标记卡顿点时，
  切窗口本身也可能带来一瞬卡顿，报告里已注明。
- 游戏退出自动收尾靠进程名加 GPU 占用判断，个别启动器会中途换掉主进程名，
  这时按 Ctrl+C 手动结束即可。
- 后台排行按进程名合并统计，显示名带 `#序号` 的是同名进程的多个实例。
- 开游戏前整备停掉的程序，只有写在 `config.json` 的 `restart` 列表里的才会在游戏退出后自动开回来；
  没写的需要自己打开（脚本会把停过的名字和路径打印出来）。

## 8. 想继续扩展的话

- 增加改动项：在 `$script:TweakCatalog` 加一条，并在生成脚本模板的 `Invoke-Tweak`
  里实现"应用 + 记日志"，同时想清楚回滚方式。
- 增加诊断规则：在 `Invoke-Diagnosis` 里加一段，用 `Add-Finding` 写结论和依据，
  需要脚本代劳的用 `Add-Tweak`，只能人工做的用 `Add-Manual`。
- 采集项：在 `Collect-System` 里加，包在 `Invoke-Read` 里（读不到会记进
  `readIssues`，不会让整个体检崩掉）。

记录模式（第 3 节）的扩展：

- 加判定规则：在 `Get-MonitorVerdict` 里加一段，用 `Add-Finding` / `Add-Manual` /
  `Add-Tweak` 写结论，阈值尽量复用 `Get-MonitorAnalysis` 已经算好的统计值。
- 加采样项：在 `Add-MonitorSystemMetrics` / `Add-MonitorGpuMetrics` /
  `Add-MonitorIoMetrics` 里加，同时补 `Test-MonitorAbility` 的可读性探测和
  `Get-MonitorTick` 末尾的补齐名单，否则报告里会出现整片 `--`。
- 改报告排版：`New-MonitorReport` 是按小节拼字符串，加小节时记得同步改
  `work\assets\使用说明.txt` 里报告怎么读那一节。
